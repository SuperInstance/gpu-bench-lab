======================================================================
PARADIGM TRADE-OFFS
======================================================================

  Bare metal (Rust, C, Zig):
    + Nanosecond tick precision
    + Runs on $4 ESP32
    + No runtime dependency
    - No built-in fault tolerance
    - Distribution is manual (TCP)

  Actor model (Elixir, Gleam):
    + Fault tolerance by default (supervisor trees)
    + Distribution built-in (BEAM clustering)
    + Hot code reload (update rooms without stopping)
    - Higher per-tick latency (~microseconds)
    - BEAM overhead on small devices

  PGAS (Chapel):
    + Write once, run distributed
    + Natural locale = room mapping
    + High-level array abstractions
    - Requires Chapel runtime on each node
    - Less mature ecosystem

  GPU (PTX/CUDA):
    + 1000× throughput for batch operations
    + Sub-ms fleet correlation at scale
    + XNOR+popcount for ternary on CUDA cores
    - Overkill for single-room ticks
    - Not available on edge devices

  WINNING COMBO:
    Bare metal on the room (Rust/C/Zig on ESP32)
    Actor model for the fleet (Elixir on RPi)
    GPU for batch analysis (CUDA on laptop)
    Chapel for research-scale distribution
